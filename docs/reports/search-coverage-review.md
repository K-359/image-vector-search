# 既存1,000枚の検索条件監査と実画像の確認

確認日: 2026-09-20

対象はQwen3.8版のmanifestに含まれる1,000枚です。[全42要求の集計](search-coverage-qwen38.md)と、そこから選んだ画像等の確認結果をまとめます。
画像の確認はアシスタントによる8枚の目視確認です。人手の独立した正解ラベル、全体の精度推定、評価セットの完成を意味しません。
既存のシーンカード・学習データ・評価データは変更していません。
今回の方針は、検索条件に基づく学習・評価データの新規構築です。この監査は旧方式の問題を把握する参考調査であり、既存データを修正して再利用する計画ではありません。
以下の「再注釈対象」「採用保留」は旧カードの問題箇所を示す所見であり、既存データの修正作業を指示するものではありません。

## 1. 分かったこと

| 条件 | カード上の全条件一致候補数 | 判断 |
|---|---:|---|
| 車 / 歩行者 | 967 / 157 | 単純な存在条件は候補がある。正確な種類・配置は画像確認が必要 |
| 自転車 / バイク | 26 / 7 | 車に比べて少ない。色・位置等で分け、train/val/testへ配分するとさらに少なくなる |
| 歩道上の歩行者 | 0 | 実画像に歩道上の歩行者が存在する例を確認。画像不足と断定せず、注釈の修正を優先 |
| 横断歩道上の歩行者 / 夜との組み合わせ | 3 / 0 | 追加の注釈確認が必要。カードの車線分類に見落とし・取り違えの可能性がある |
| 濡れた路面 / 霧 | 3 / 0 | 候補が少ない。未記載の画像を確認するまで母集団の不足とは確定できない |
| バスと自転車 / 赤い車と白いバス | 3 / 3 | 複合条件の候補が少ない。追加画像の探索候補 |
| 同じ車線の正面向き自転車 | 1 | 交差点の画像で車線関係を確定しにくい。正例が1枚あるとはまだ言えない |

候補数は要求間で重複します。正解数でも、必要件数から逆算した不足数でもありません。

## 3. 画像不足と注釈不足を分ける

カードに登場する歩行者221対象の `lane_relation` は、`roadside_left=65`、`roadside_right=133`、
`crosswalk=3`、`same_lane=19`、`oncoming_lane=1` でした。全対象を通じて `sidewalk` は0件です。
歩道上の歩行者を確認できる画像があるため、新規生成では歩道・路肩の区別を検証する必要があります。
ただし、歩行者の全対象を路肩から歩道へ機械的に置き換えてはいけません。

天候の記録は `clear=681`、`snow=180`、`overcast=77`、`rain=61`、`partly_cloudy=1` です。
目視したsnow群の3枚はいずれも雪の根拠が見当たりませんでした。
これは再検査の理由になりますが、残り177枚も誤りであるとは断定できません。
スキーマ上の天候には `unknown` が用意されていないため、新規生成では不明を許す設計も検討します。
原因がモデル、生成プロンプト、構造化出力、別の処理のどこにあるかは、この監査では特定していません。

## 4. 新規構築への反映

1. 条件別の生成件数を管理し、車などの頻出対象へ偏ることを防ぐ。
2. 天候、道路上の位置、対象の種類、クエリと制約の一致を、新しく生成するデータの検証項目にする。
3. 記載の欠落を対象の不在とみなさず、判定不能を扱えるスキーマ・判定方法を設計する。
4. 静止画で確認できる条件と、動画・道路情報が必要な条件を分ける。

次の作業は、[検索要求一覧](../search-requirements.md)を基にした目標件数・画像選定・新規生成・分割の設計です。
この監査の画像確認を、凍結した人手評価セットの代用にはしません。

# 新規データ用の検索条件一覧 v1

確定日: 2026-09-24

新しく作る5,000枚（学習3,500・検証500・評価1,000、試行50枚を含む）の画像選定に使う条件一覧です。
条件IDと必須条件をこの版で固定します。画像はまだ選定しておらず、どの条件にも充足実績はありません。
基準クエリは意味を確認するための表現であり、生成済み学習データではありません。
既存の生成済みラベルは引き継ぎません。

## 1. 件数と利用区分

| 区分 | 条件数 | 利用方針 |
|---|---:|---|
| 基本条件 OBJ〜CB | 200 | 学習・検証・評価に配置する対象 |
| 評価専用の組み合わせ H01〜H20 | 20 | test専用。構成要素の学習実績を確認して採用 |
| 希少対象 R01〜R03 | 3 | 学習・検証・評価に配置する対象。不足を独立に集計 |
| 追加の注釈・判定 X01〜X04 | 4 | 必要な座標・全数確認・不在確認・OR判定を実装後に使用 |
| 危険行動 D01〜D06 | 6 | 要求として保持。動画等と判定規約が揃うまで未評価 |
| **計** | **233** | **静止画の選定対象227条件、追加情報待ち6条件** |

200条件の内訳は、存在7・色24・画面位置21・道路上の位置27・向き12・道路設備16・時間帯天候8・共存21・組み合わせ64です。
組み合わせ64は、環境と対象24・同じ対象の複数属性16・複数対象への属性の結び付け24です。
これらは意味の異なる検索条件の数です。画像数・生成文数・学習ペア数とは一致しません。
条件ごとの目標画像数は[配分CSV](search-condition-allocation.csv)、5,000枚の選び方は[画像配分と選定手順](image-selection-plan.md)に固定しました。

## 2. 表の読み方と判定規約

- 同じ行の必須条件はすべてANDで結びます。X04だけは明示したORです。
- 「対象A」の種類・色・位置・向きは同じ個体に要求します。「対象B」はAとは別個体です。全対象の総数はX02以外で制限しません。
- 例えば赤い車と白いバスの条件は、白い車と赤いバスでは満たしません。ただし他にも赤い車と白いバスがいれば適合です。
- 「場面: 工事区間; 対象A: 自転車」は同一画像に両方が見える条件です。自転車が工事区間内に接地するとは要求しません。道路との位置関係は明記された場合だけ要求します。
- 「—」は対応する旧要求例IDがないことを表します。既存のS/X/Dは設計例の識別子であり、旧データのラベル参照ではありません。
- [正解判定基準](search-requirements.md)の適合・不適合・判定不能の3区分を適用します。未記載は不在の根拠にしません。
- 色は車体の主な塗装色です。自転車はフレーム、バイクは車体・外装を見ます。乗り手の服色・タイヤ色・照明の色で代用しません。複数色で主色を決められない場合や白と銀の区別がつかない場合は判定不能です。
- 左・中央・右は可視部分の矩形中心で画面を横3等分した区画とします。境界や遮蔽で位置が安定しなければ判定不能です。試行で規約を変更する場合は版を更新し、試行分も再判定します。
- 自車線・隣接車線はカメラ搭載車を基準とします。交差点内などで対応が定まらなければ判定不能です。歩道・横断歩道・車道は排他的ではなく、横断歩道が車道上なら両方が成立します。
- 正面・背面は前後を識別でき、その面がカメラ側に向くことを要求します。側面だけ、または向きの境界が曖昧なら判定不能です。移動・停止の推測は加えません。
- 下表にない天候・時間帯・背景・動作を、クエリの必須条件として追加しません。

### 場面条件の境界

| 条件 | 採用に必要な観察根拠・紛らわしい場合の扱い |
|---|---|
| 市街地／住宅街／田舎道 | 商業・業務等の建物が連なる道路／住宅を中心とする街区／田畑・森林等を中心とする道路。住宅街と市街地は重複可。見える範囲で判断できなければ不明 |
| 高速道路 | 専用道路を示す標識等の識別可能な根拠。広い、多車線、車速が高そうという推測だけでは採用しない |
| トンネル内／橋上 | カメラが内部／橋上の道路に位置する根拠が必要。遠方にトンネル・橋が見えるだけでは不適合 |
| 交差点／横断歩道 | 道路の交差・分岐、または横断歩道標示を確認。車両や歩行者の配置だけから推測しない |
| 工事区間 | 工事標示・掘削・工事用設備などで道路工事と確認。コーンだけで用途不明なら判定不能 |
| 赤／青／黄信号 | 車両用信号の灯火を識別。青は通常の緑色灯火を含む。異なる信号で複数色が見えれば複数条件に適合。適用車線や違反は要求しない |
| 濡れた路面／積雪路面 | 路面上の水膜・水反射等／路面上の雪を確認。影・白線・路肩だけの雪と区別。降雨・降雪の証拠には流用しない |
| カーブ／坂 | 道路自体の水平な曲がり／上り下りを視認。交差点の曲がり角やカメラの傾きだけでは採用しない |
| 昼／夜／薄明 | 日中の自然光／夜間／夜明け・日暮れの薄明を示す根拠。トンネル内の暗さだけで夜とはしない。識別できなければ不明 |
| 晴れ／曇り | 空・雲・日射の視覚的根拠から判断。部分的な雲だけで曇りに固定しない。夜・トンネル等で空や日射が確認できなければ不明 |
| 降雨／降雪／霧 | 降水中／降雪中／霧の存在の視覚的根拠。路面・ガラスの水滴、積雪、煙、レンズの汚れだけで断定しない |
| 緊急車両 | 車体形状・標章等から救急・消防・警察などの緊急用途を識別。赤色灯だけで車種を確定せず、実際の緊急走行は要求しない |
| 列車／動物 | 実物の鉄道車両／人以外の動物を視認。看板・ポスター・模型を除外。小さく識別できなければ不明 |

### 紛らわしい負例の作り方

色・左右・種類・場面等の必須条件のうち1つだけが異なる候補を優先して探します。
別条件の正例だからといって自動的に負例にせず、画像全体に元の検索条件を満たす別対象がないことも確認します。
CBの隣り合う2行は属性を入れ替えた比較用の組ですが、両方を満たす画像もありえます。
共存条件では片方の不在を確認し、X02・X03では対象数の上限付きカードから全数・不在を推測しません。
具体的な適合・負例・判定不能の例は[既定の要求例](search-requirements.md)を共通基準として使います。

## 4. 評価専用の組み合わせの管理

H01〜H20は「学習クエリに含めない条件の組み合わせ」を評価する枠です。
言い換えも同じ条件IDとして管理し、train・valのクエリには使いません。
条件を付け足してH条件を含ませたクエリもtrain・valから除外します。生成を自由記述へ拡張するときも、文字列一致ではなく対象への属性の結び付けと条件の包含関係で検査します。

構成要素となる対象・属性・場面条件は学習側に採用済みの事例が必要です。
例えばH08（画面右の青い車）は、COL04（青い車）とPOS03（画面右の車）の学習事例を確認します。
H01ならENV02（夜）とPOS16（画面左の自転車）などの構成要素を確認します。
要素の学習事例やtest側の確認済み正例・負例が不足すれば、そのH条件は未評価として残します。
H条件の結果を用いたモデル選択はせず、基本条件のvalで調整します。

学習画像にH条件に相当する場面が偶然写っていることまで禁止する設計ではありません。
したがって結果は「未学習のクエリ条件の組み合わせ」として報告し、視覚的に未経験の場面への汎化とは主張しません。
画像・撮影系列・近似画像のtrain/val/test間の漏れは、これとは別に防ぎます。

## 5. 用途・充足状況・範囲の記録

- U01（一般検索）: 静止画の227条件すべて。
- U02（安全確認）: 歩行者・自転車・バイクを含む条件、道路上の位置、工事・信号・路面・視界に関する条件、X01〜X03を重点集計。
- U03（危険場面）: D01〜D06を独立管理。LOC01・LOC27・CA13・CE20・X01等は関連静止画を探す条件として併記できるが、危険行動の達成件数には加算しない。

各IDについてsplit別の適合画像数・確認済み不適合画像数・判定不能数、撮影系列数を記録します。
一つの画像が複数IDを満たしても、5,000枚の総数では1枚です。
目標未達と、必要な情報がなく判定自体ができない状態を分けます。条件数・言い換え数を増やして充足したように扱いません。

この233条件は今回の初版であり、可能な検索条件の全組み合わせではありません。
分類文書に挙げた以下の条件は要求候補として残し、この版の233条件の達成率には含めません。

| 今回の固定一覧の外に残る条件 | 扱い |
|---|---|
| 左右の路肩、画面内の奥行き区分 | 注釈境界を決めて次版で条件IDを追加。歩道や物理距離で代用しない |
| 横向き・斜め向き、同じ種類の複数個体への属性付与 | 次版の対象。前後向き・異なる種類の共存で達成扱いにしない |
| 車種詳細、服色、文字・標識内容 | 解像度と注釈規約を確認して拡張 |
| 停止・駐車、正確な日時・場所 | 時系列・信頼できるメタデータの利用方法を別途設計 |

D01〜D06の「急」等の閾値・必要な動画・信号運用の規約は未確定です。
[検索要求と正解判定基準の危険行動の表](search-requirements.md#4-危険行動そのものの検索要求6件)を参照し、静止画だけで適合ラベルを作りません。

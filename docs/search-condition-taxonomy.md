# 車載画像検索で扱う検索条件の定義（初版）

作成日: 2026-09-20

この文書は、学習・評価データを作る前に「何を検索できるようにするか」を定めるためのたたき台です。
対象用途は、一般的な交通シーン検索、安全確認、危険場面検索のすべてです（ユーザー指定）。
学習・評価データは最初から作り直します。定義した検索条件に基づき、元画像群からの画像選定、クエリ生成、正解付け、分割を新たに設計します。
以前の1,000枚に対する生成済みクエリ・ラベルの修正や継ぎ足しは、今回の構築方針に含めません。
データ生成コードへの実装、カテゴリ別の必要件数、学習の実行は次の段階で扱います。

## 1. 対象とする検索

日本語の検索要求に対し、その条件を満たす車載カメラの静止画像を探します。
まずは画像上で確認できる対象物・属性・配置・道路環境を対象とします。
検索条件の種類と、条件を組み合わせる複雑さを別々に管理します。
例えば「夜の画像」は環境条件だけの検索、「夜の横断歩道上に歩行者がいる画像」は環境・道路設備・対象物の組み合わせです。

| 用途ID | 対象用途 | 検索したい内容の例 | 評価で確認すること |
|---|---|---|---|
| U01 | 一般的な交通シーン検索 | 車種・色・配置、道路設備、天候、昼夜、複数対象 | 幅広い条件とその組み合わせを検索できるか |
| U02 | 安全確認に関わる検索 | 歩道・車道・横断歩道上の歩行者、自転車・バイクの位置と向き、工事区間、見通しの悪い環境 | 歩行者・自転車などの少数カテゴリでも条件を見分けられるか |
| U03 | 危険場面検索 | 逆走、飛び出し、急な横断、急停止、急接近、信号無視 | 危険場面の候補を探せるか。行動自体の適合判定には必要な時系列・道路情報があるか |

用途は排他的ではなく、1つの検索要求が複数用途に属して構いません。
U03も要求範囲に含めますが、静止画のみで評価できる観察条件と、追加情報が必要な行動条件を別に記録します。
関連する静止画が取得できただけで、危険行動そのものの検索に成功したとは数えません。

## 2. 検索条件の分類

「基本」は初版で対象とする条件、「追加」は必要性と注釈方法を確認してから加える条件です。
基本カテゴリでも、画像から判別できない属性を推測で埋めません。

| ID | 条件の種類 | 検索例 | 正解判定で確認すること | 初版の扱い |
|---|---|---|---|---|
| C01 | 対象物の存在・種類 | 歩行者がいる／自転車が写っている | 指定した種類の対象が見える | 基本 |
| C02 | 対象物の属性 | 赤い車がいる／白いバスがいる | 種類と色が同じ対象に属する | 基本 |
| C03 | 画面内の位置 | 画像の右側に自転車がいる | 指定対象が指定領域に見える | 基本 |
| C04 | 道路・自車に対する位置 | 歩道上に歩行者がいる／自車と同じ車線に車がいる | 対象と歩道・車線などの対応が確認できる | 基本 |
| C05 | 対象物の向き | こちらに正面を向けた車／後ろ姿が見える自転車 | 正面・背面・横向きなどが見分けられる | 基本 |
| C06 | 道路の種類・設備・状態 | トンネル内／赤信号が見える／路面に雪がある | 指定した道路・設備・状態が確認できる | 基本 |
| C07 | 明るさ・時間帯・天候 | 夜の道路／霧で視界が悪い道路 | 視覚的な根拠がある。時間帯は正確な時刻とは区別する | 基本 |
| C08 | 複数対象の共存 | バスと自転車がいる／赤い車と白い車がいる | 各条件を満たす対象が存在し、別対象への属性の取り違えがない | 基本 |
| C09 | 対象物同士の位置関係 | トラックの左側に自転車がいる | 指定した2対象の対応と左右関係を確認できる | 追加 |
| C10 | 数量・否定・選択条件 | 車がちょうど2台／歩行者がいない／バスまたはトラックがいる | 数える範囲、見落とし、否定・ORの意味を定義できる | 追加 |

### 条件値と境界

- **対象物**: 車、バス、トラック、バン、バイク、自転車、歩行者を基本とします。緊急車両・列車・動物は希少対象として別集計します。乗り手と自転車・バイクの扱いは注釈規約で統一します。
- **属性**: 初版は色を対象とします。車種の詳細・文字・標識内容の読み取りは、必要性と解像度を確認して追加します。
- **画面内位置**: 左・中央・右、画面上の手前側・中間・奥側を区別します。「右側」だけなら奥行きや車線を要求しません。奥行きの区分を物理的な距離に置き換えません。
- **道路に対する位置**: 同一車線、左右の隣接車線、対向車線、歩道、横断歩道、左右の路肩を区別します。車線構造が不明な画像は判定不能とします。
- **向き**: 正面、背面、左向き、右向き、斜めを扱います。向いている方向と実際の移動方向は別です。
- **道路・設備**: 市街地、住宅街、高速道路、トンネル、橋、交差点、横断歩道、工事区間、信号色、濡れた路面、積雪などを扱います。各値に肯定例・紛らわしい例・判定不能例を用意します。
- **環境**: 昼・夜・薄明、晴れ・曇り・雨・雪・霧などを候補とします。「濡れた路面」と「降雨」、「積雪」と「降雪」を別条件にします。曖昧な画像を無理に分類しません。
- **共存**: まず2対象を中心とします。対象が共存することと、対象間の特定の位置関係が成立することを分けます。

## 3. 条件の組み合わせと表現

カテゴリごとの単独条件と、カテゴリをまたぐ組み合わせの両方を作ります。
分類タグは複数付与できるものとし、タグ別件数の合計をクエリ総数として扱いません。

| 段階 | 狙い | 例 | 最低限満たす意味上の条件 |
|---|---|---|---|
| 単独 | 基本の対象・環境を検索する | 歩行者がいる画像／夜の画像 | 歩行者の存在／夜 |
| 属性・位置付き | 同じ対象の属性・位置を見分ける | 赤い車／右側の自転車 | 車かつ赤／自転車かつ右側 |
| 環境との組み合わせ | 対象と背景条件を両方満たす | 夜の歩道上に歩行者がいる画像 | 夜、歩行者、歩道上 |
| 複数対象 | 属性を正しい対象に結び付ける | 赤い車と白いバスがいる画像 | 赤い車の存在、白いバスの存在 |

言い換えは別の軸で管理します。「右側に自転車」「自転車が右に写っている」は同じ条件です。
短いキーワード、自然な文、会話的な要求を含めますが、言い換えの数を条件の多様性と混同しません。
未知の組み合わせへの評価を作るときは、文章の一致だけでなく意味上の条件の組み合わせを管理します。
単独条件の評価と、未学習の組み合わせに対する評価は分けて報告します。

## 4. 正解判定の共通規則

1. クエリに明示された条件と、語の意味上必要な条件だけを正解判定に使います。撮影元画像の天候・時間帯・背景を勝手に追加しません。
2. 「赤い車」の色と種類は同じ対象に結び付けます。「赤いバスと白い車」は正例になりません。
3. AND条件では、指定されたすべての条件を満たすことを要求します。条件の一部だけを満たす画像は、どの条件が不一致か説明できる場合に負例候補とします。
4. 事実の欠落と否定を区別します。シーンカードに対象が書かれていないだけでは、その対象が画像に存在しないとは判断しません。
5. 判定結果は設計上「適合」「不適合」「判定不能」を区別します。遮蔽、小ささ、暗さなどで確認できない画像を、自動的に負例へ変換しません。
6. 位置の参照基準を明示します。C03は画像座標、C04は自車・道路構造、C09は指定した対象を基準とします。

例: 「右側に赤いバスがいる」の必須条件は「バス」「赤」「画面右側」です。
昼・夜、晴れ・雪、自車と同じ車線かどうかは、そのクエリの判定条件に含めません。

## 5. 動き・危険場面・メタデータの扱い

危険場面を検索したい要求は、検索したい目的として記録し、画像で確認できる根拠と対応付けます。
その根拠を検索できることと、危険行動そのものを正確に判定できることは別に評価します。

| 検索したい内容 | 静止画で扱える関連条件の例 | 行動・状況の断定に追加で必要な情報 |
|---|---|---|
| 逆走 | 対向きの対象、自車線・対向車線との位置関係 | 実際の移動方向、道路の通行方向。正面を向いているだけでは逆走とはしない |
| 飛び出し・急な横断 | 車道上の歩行者、車両脇の歩行者 | 時系列での移動、出現前後の状態 |
| 急停止・急接近 | 前方車両の存在・配置 | 時系列、距離や速度の変化 |
| 信号無視 | 赤信号の存在、車両の配置 | 対象車両に対応する信号、停止線、通過時点の状態 |
| 停止・駐車 | 道路上・路肩・駐車区画内の車両 | 時系列や状況情報。位置だけから停止・駐車を確定しない |
| 指定日時・場所の画像 | 画像だけでは正確な日時・場所を確定しない | 信頼できる撮影日時・GPS等のメタデータ |

危険場面も検索要求に含めます。まず上記の観察可能な条件を定義し、行動の判定に必要な動画・道路情報の有無を別途確認します。
情報が不足する行動条件は「未評価・追加情報待ち」として残し、要求範囲から削除したり、達成済みと扱ったりしません。
実験用にランダム付与された日付は、実際の撮影日時の正解ラベルとして使いません。

## 6. 現在の実装との対応

以下は定義を実装する際の確認事項であり、この文書の追加によってデータ生成の挙動は変わりません。

| 条件・規則 | 現在の実装 | 次段階の確認事項 |
|---|---|---|
| C01〜C08 | `scene`、`required_scene`、`participants`、`required_participants` に概ね対応する項目がある | カテゴリ指定生成と件数管理が必要。既存語彙があるだけでは生成の網羅性は保証されない |
| 単独条件 | `--min-constraints` の既定値は2 | 「夜」「歩行者の存在」など1条件のクエリを採用する設計が必要 |
| 粗い位置指定 | 位置語彙は `foreground_right` など奥行き込みの区分 | 「右側」だけなら右側の複数区分に適合するようにする。奥行きを勝手に要求しない |
| C09 | 対象物同士の関係を保持する専用項目がない | 対象IDと関係の表現・判定が必要 |
| C10 | 複数対象への重複しない割当はあるが、正確な総数・否定・ORを明示する仕組みはない | 注釈範囲、スキーマ、判定方法の追加が必要 |
| 判定不能 | 一部属性に `unknown` があるが、最終的なペアラベルは二値 | 不明な条件を負例へ変換しない採用規則が必要 |
| クエリと制約の一致 | `--ground-constraints` は既定無効。既存処理はキーワード照合 | 単純に有効化するだけで解決とせず、条件から文章を生成し、対応を検証する方法を検討する |
| 動き | `motion` の語彙と条件がある | 基本セットでは観察可能な位置・向きと区別する。動画が必要な要求を別管理する |

実装参照: [データ生成スクリプト](../scripts/build_reranker_dataset.py)

## 7. 次に決めること

具体的な検索要求と正例・負例・判定不能の基準は、[検索要求と正解判定基準](search-requirements.md) にまとめています。
2026-09-24に、画像選定に使う[検索条件一覧 v1（233条件）](search-condition-catalog.md)を固定しました。以下の1の列挙は完了しています。一覧外の拡張候補は同文書に残しています。

1. U01〜U03の各用途について必要な条件値と組み合わせを列挙します。車だけでなく歩行者・自転車の条件を個別に確認できる構成にします。
2. 選んだ条件について、正例・紛らわしい負例・判定不能の具体例を確認し、位置などの境界を注釈規約に落とします。
3. カテゴリ、対象物、条件の組み合わせごとに学習・検証・評価の目標件数と画像選定方法を決め、元画像群から新たに候補を選びます。画像内にない条件を生成で補いません。
4. 実際の利用頻度に沿う評価と、少数カテゴリも個別に確認する評価を用意します。カテゴリ別件数・成績を示し、全体平均だけで判断しません。

すべての用途を対象とし、静止画で構築する最初のセットは「C01〜C08と、その明示的なANDの組み合わせ」を暫定案とします。
C09・C10は追加の注釈・実装が必要な条件、動画で判定する行動は追加情報が必要な要求として保持します。
メタデータ検索は画像との適合を学習する処理と分けて設計します。
